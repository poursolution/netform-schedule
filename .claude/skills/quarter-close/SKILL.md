# 분기 마감 도우미

운영 룰의 단일 출처는 `OPERATIONS.md` (§1 귀속, §2 마감일, §6 정산 상태, §8 2라운드 확인, §9 마감, §15 체크리스트). 숫자 계산은 `src/utils/settlement.js` · `src/utils/quarterlySettlementCore.js`. 이 스킬은 그 순서를 실제 화면 위에서 따라가게 하는 매뉴얼이다.

## 절대 규칙

- 사용자에게는 존댓말.
- **읽기만 한다.** 아래 버튼은 사용자가 이번 대화에서 그 버튼을 콕 집어 "눌러"라고 했을 때만 누른다:
  정산 생성/갱신 · 리마인드 · 최종확정 요청 발송 · 전체 최종확정 · PDF + Excel 발송(김유림) · 분기 마감 · 마감 해제 · 결과 입력(1~4 키 포함) · 체크박스.
- 비밀번호는 입력하지 않는다. 로그아웃 상태면 "브라우저 창에서 로그인해 주세요" 한 줄로 요청하고 기다린다.
- 운영 Firebase에 직접 붙지 않는다(자격증명 없음). 화면 = 내장 브라우저로 `https://schedules-cip.pages.dev` 를 연다.
- K-APT 공고 확인은 앱 안 자동 루트(Worker + 잔디 크로스체크)가 이미 있다 — 사용자에게 사이트에 직접 가 보라고 하지 않는다 (CLAUDE.md §1).

## 0. 어느 분기인가

- 사용자가 말한 분기(예: "3분기" → 올해 `YYYY-Q3`). 말이 없으면 `defaultQuarterKey()` 기준: 지난 분기 마감일(다음 달 30일) 전이면 지난 분기.
- 마감일·급여 반영월: OPERATIONS.md §2 표. 오늘이 마감일을 지났으면 첫 줄에 "마감일 N일 지남"을 적는다.

## 1. 현황 읽기 (읽기 전용)

내장 브라우저에서:

1. **실적** 화면 → 상단 분기 셀렉트를 대상 분기로. 읽을 것:
   - KPI 줄(PT 건수 · 승/무/패 · 결과 미입력)
   - 처리 큐 3칸: 검토필요(K-APT 미확인) · 결과 미입력 · 정산요청 대기
   - 엑셀이 필요하면 `내보내기 ▾ → 엑셀 (.xlsx)` — 담당자별 요약(예상 금액 · **분기정산 금액**) + 상세. 사용자가 받기를 원할 때만 누른다(파일 다운로드).
2. **분기정산** 화면(실적 우측 상단 `분기정산` 또는 사이드바 `정산`). 단계 줄 5칸을 그대로 읽는다:
   1. 분기정산 생성 (생성 시각·생성자)
   2. 담당자 1R 확인 (`확인 / 전체`, 미확인자 이름)
   3. 검증요청 처리 (검토필요 N건 · 수정요청 N건)
   4. 최종확정 2R (`확정 / 전체`)
   5. 김유림 발송 (발송 완료 여부)
   그리고 블루 카드의 금액 · 정산 대상 건수 · 신뢰도(%) · 마감 D-day.

숫자 대조: 실적 엑셀의 **분기정산 금액 합계 = 분기정산 화면 금액**이어야 한다. 다르면 그 사실과 두 숫자를 그대로 보고하고 원인 추정은 "확인 필요"로 둔다.

## 2. 보고 형식

```
2026 Q3 마감 현황 (마감 10/30 · 급여 10월 · 오늘 기준 D+2)
금액 6,750,000원 · 정산 대상 27건 · 신뢰도 92%

✅ 1. 분기정산 생성 — 10/24 관리자
⏳ 2. 1R 확인 3/5 — 미확인: 한준엽, 조재연
⏳ 3. 검토필요 16건 — 실적 > 검토필요 필터에서 처리
⬜ 4. 최종확정 0/5 — 2·3 끝나야 요청 가능
⬜ 5. 김유림 발송

다음에 하실 일: 검토필요 16건 처리 (실적 → 검토필요 칸 클릭)
```

- 단계마다 ✅ 끝 / ⏳ 진행 중 / ⬜ 아직. "다음에 하실 일"은 **하나만**.
- 막혀 있는 단계는 왜 막혔는지(버튼 비활성 사유) 한 줄.

## 3. 단계별 안내 (사용자가 하거나, 콕 집어 시킬 때만 대신 누름)

| 단계 | 어디서 | 끝난 기준 |
|---|---|---|
| 검토필요 처리 | 실적 → 검토필요 큐 → 행 선택 → K-APT 재검증 / 취소공고 / 수동 승인 | 검토필요 0, 수정요청 0 |
| 결과 미입력 | 실적 → 결과 미입력 큐 → 담당자에게 입력 요청(리마인드) | 미입력 0 (또는 사유 확인) |
| 1R 확인 | 분기정산 → `미확인 N명 리마인드` (잔디 발송 = 사용자 확인 필요) | 전원 이상없음 |
| 최종확정 | 분기정산 → `최종확정 요청 발송` | 전원 최종확정 |
| 김유림 발송 | 분기정산 → `PDF + Excel 발송` | 발송 완료, reportVersion 기록 |
| 분기 마감 | 분기정산 → `분기 마감` | `closed = true` |

마감일 당일 체크(OPERATIONS.md §15): 전원 최종확정 → 김유림 발송 → 분기 마감 → 활동 로그 확인. 마감 해제는 남발 금지(§9) — 요청받으면 이유를 한 번 확인한다.

## 4. 자주 나오는 질문

- "왜 금액이 실적이랑 달라?" → 실적 엑셀의 `예상 금액`은 결과가 있는 모든 건, `분기정산 금액`은 정산요청·수동확인된 대상만(이전 분기 미지급 이월 포함). 조현식은 정산 제외 대상.
- "이 PT 왜 빠졌어?" → OPERATIONS.md §4 제외 기준(본인PT·본인영업·주담 패배·무 지원·취소공고·미검증)과 §1 확정일 귀속 순서로 확인.
- "마감 지났는데 아직 안 끝났어" → 남은 단계와 막힌 사람 이름을 먼저, 긴급 우회(§8)는 사용자가 원할 때만 안내.
